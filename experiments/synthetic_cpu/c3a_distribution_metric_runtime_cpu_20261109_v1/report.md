# 多样本评分工具单图像 CPU 耗时诊断

## 问题与协议

为判断独立评分原型在补充评价设计的代表图幅上是否有明显 CPU 计算负担，按预登记[协议](protocol.json)生成固定随机种子的 `[16,256,256]` 预测数组和 `[256,256]` 观测数组。值均匀分布于 `[0,1]`。每项评分先预热一次，再顺序计时 7 次；数组生成、模块导入及文件写入不计入评分耗时。设备为 CPU，没有训练或模型推理。

## 结果

| 评分量 | 中位数（毫秒/单张） | 第25–75百分位（毫秒） | 最小–最大（毫秒） |
|---|---:|---:|---:|
| 逐像素 CRPS | 16.700 | 15.884–17.801 | 13.683–19.866 |
| 归一化整图能量分数 | 7.183 | 6.925–7.363 | 6.639–7.506 |
| 邻接变差分数 | 14.568 | 14.482–15.653 | 14.322–17.940 |

21 条逐次记录中每个评分量各有 7 次；评分值均为有限数。汇总见[结果 JSON](结果.json)，逐次计时见[CSV](逐次计时.csv)，运行环境和文件 SHA-256 见[manifest](manifest.json)。运行使用 Python 3.13.5、NumPy 2.1.3。

## 运行故障记录

首次直接执行冻结命令时，Python 未把仓库根目录加入模块搜索路径，脚本在导入 `scripts.distribution_metrics` 时以 `ModuleNotFoundError` 退出；该次没有生成评分或计时结果。根因由脚本目录、仓库根目录和模块实际路径核对确认。随后在运行器中加入基于脚本位置的仓库根目录解析，并用同一命令重跑；以上结果来自成功运行，manifest 中保存了成功运行所用脚本摘要。

## 解释边界

- 这些数字只描述当前主机、单一图幅大小、单一 draw 数和当前 NumPy 实现；不能直接乘以 200 视为开发集总时间，也不能外推 GPU 耗时。
- 未计模型采样、输入读取、输出保存、统计重抽样或并发运行成本；未测峰值内存。
- 该诊断只用于未来评价协议的粗略 CPU 成本参考，不推荐真实模型 draw 数、不设正式运行预算、不证明指标的科学有效性，也不改变 C3-A v3、训练状态、数据权限或阶段 gate。
- 未读取项目图像、模型、检查点、既有实验预测或指标；未访问 confirmation/test 载荷或测量值。
