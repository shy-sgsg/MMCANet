# C3-A 基线 checkpoint 合同核验

## 目的

核对冻结的 C3-A SAR-only Flow 筛选协议，能否绑定现有 C2 `x2_light` SAR-only 基线、train/development 固定输入元数据及其 checkpoint，并确认基线模型可在 CPU 上严格加载。

## 结果

- 冻结 C3-A 协议 SHA-256 为 `147c361b3e91bc4cd8d76ce5c464ad9d2137f2d06b38f31a0bc7c7a7e93101a7`，与本地 runner 中的协议绑定一致。
- C1 来源清单哈希与协议记录一致；train 与 development 固定输入的 `manifest.json`、`files.csv` 哈希与 C2 SAR-only 基线运行记录一致。核验仅读取这些清单/CSV 字节，不解析身份行或加载数组。
- C2 基线清单状态为 `complete`，配置为 `x2_light`、`sar_only`，最优轮次为 30；清单中的 confirmation/test 访问和使用标记均为 false。
- checkpoint SHA-256 为 `8255b5229ca1e041cb59aed582d794bb67afdbe1601b6f4dc425c43ce27f7165`，与冻结 C3-A 协议和 C2 基线清单相符。使用 `weights_only=True` 在 CPU 加载后，`C2MatchedJoint(scale=2, optical_enabled=False, width=32, blocks=4, hr_width=16)` 的 `strict=True` 参数匹配通过；96,209 个参数均为有限值。
- 全零合成输入 `[1,1,128,128]` 得到有限输出 `[1,1,256,256]`。这是结构/尺寸冒烟，不是数据评价或模型质量证据。
- C3-A Flow 的正式运行目录当前不存在。

## 解释边界

本记录只证明静态协议/元数据绑定和既有 SAR-only checkpoint 的 CPU 结构兼容性。它没有运行 C3-A Flow 训练、没有评价真实图像、没有复算基线开发指标、没有读取图像数组或光学输入，也没有访问 confirmation/test 载荷。C1 v2 的 confirmation 继续封存。训练仍按用户要求暂停；本核验不改变 C2/C3 阶段 gate。

受控本地固定输入和 checkpoint 不提交到 Git；没有必要清理或复制这些数据。检查时分区剩余约 9.5 GiB，本审计只新增小型文本与脚本。
