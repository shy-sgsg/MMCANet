# C3-A GPU 启动前置核验

## 核验目的

用户已授权执行冻结的 C3-A SAR-only Flow Matching 实验。本报告只记录训练启动资格和入口保护，不是训练、推理或模型评价结果。

## 冻结条件

- 训练协议：`protocols/mmcanet_phase_c3a/sar_only_flow_c1_v2_20261105_v1.json`，SHA-256 为 `147c361b3e91bc4cd8d76ce5c464ad9d2137f2d06b38f31a0bc7c7a7e93101a7`。
- 资源约束：CUDA GPU、空闲显存至少 3 GiB，`concurrent_gpu_training=false`。
- 本轮训练只允许使用 C1 v2 的 train/development 固定 SAR LR 和 noisy pseudo-target，不访问 optical、confirmation 或 test。

## 代码与输入核验

- 任务在基于提交 `13a3c91ca9c252c146361a42247321f251834b55` 的隔离 worktree 中执行；主工作区状态数量复核为 6,011 项，未修改主工作区。
- 固定 `x2_light` train/development 清单分别为 1,600/200 个身份、92/19 个来源组。数组完整性验证只读取这两个角色的 SAR LR 与 target；worktree 未链接 optical、confirmation 或 test 载荷目录。
- 既有 C2 SAR-only baseline checkpoint SHA-256 为 `8255b5229ca1e041cb59aed582d794bb67afdbe1601b6f4dc425c43ce27f7165`，CPU `weights_only=True` 加载及匹配模型 `strict=True` 加载通过。
- 干净提交缺少 C3-A 所需的本地 loader、对照模型与指标接口；隔离分支补齐最小运行依赖、C3-A 专用指标及可选样本归档 sidecar。归档 sidecar 只保存同一冻结 v3 采样循环的数组和表示域亮值描述，不改变选模或 gate。
- 针对性回归 95 项通过；相关 Python 文件 `py_compile`、训练/评价入口中文 `--help` 与 `git diff --check` 通过。软件回归不替代真实 GPU 模型运行。

## GPU 快照与启动结果

2026-11-23 13:19（主机显示时间）提权 `nvidia-smi` 快照：RTX 3050 Laptop，总显存 4,096 MiB，已用 1,231 MiB，空闲 2,865 MiB（2.80 GiB），GPU 利用率 87%。驱动进程清单显示 PID `426517` 的 AISAR Python 计算进程占用 278 MiB。该任务身份未知，因此按并行计算风险保守处理。

训练入口的提权预检在正式输入读取前退出，退出码为 2；未创建固定 C3-A run 目录，没有读取影像载荷。普通沙箱无法读取 `nvidia-smi` 计算进程清单；提权入口可正常核验。

13:32 的刷新快照仍见相同 PID，空闲 2,803 MiB（2.74 GiB）、利用率 6%；13:42 空闲 2,212 MiB（2.16 GiB）、利用率 99%，并短时看到 532 MiB MATLAB 图形占用；13:57 空闲 2,865 MiB（2.80 GiB）、利用率 98%，MATLAB 大额图形占用已消失。各次仍见同一 AISAR Python PID。冻结入口直连复核在数据读取前以退出码 2 阻止运行。等待器一次子进程在 13:30 以 `-6` 无诊断退出且未创建 run 目录；紧接的 GPU 刷新与直连入口复核均正常，未复现该信号退出。后续等待器对无诊断信号退出最多重试一次，再停止并保留日志。
14:06 第 32 次预检已不再发现 AISAR Python PID，也没有其他 CUDA 计算进程；CUDA 返回可用显存 2.67/3.67 GiB，仍比冻结门槛少约 0.33 GiB。入口因此在创建正式 run 目录和读取影像前退出；等待器继续每分钟复查显存门槛。

14:19 第 45 次预检仍无其他计算进程，CUDA 可用显存依旧为 2.67/3.67 GiB；连续预检仍未创建 run 或读取图像。14:24 第 49 次预检又发现 AISAR Python PID `589855`，提权 `nvidia-smi` 显示该进程占 166 MiB、总显存空闲 2,977 MiB（2.91 GiB）、利用率 73%；进程和显存两项 gate 均未通过。等待器继续保持每分钟检查。

最初预检把两个桌面图形上下文也计为计算进程。`nvidia-smi --query-compute-apps=pid,process_name` 核验它们分别为 `/usr/bin/nautilus` 和 `/usr/bin/resources`。当前实现只忽略这两个确定的桌面进程，其他未知计算进程仍阻止启动；新增回归测试验证 AISAR Python 仍会被拦截。冻结 JSON、资源阈值、seed、训练设置、评价和停止条件未改。

## 决定与下一步

当前仍有高利用率 AISAR Python CUDA 计算，且空闲显存低于 3 GiB；不与其并行训练，不终止该进程，也不降低门槛。待其结束后重新执行同一冻结入口；只有进程条件和 3 GiB 显存门槛同时通过，才开始 5 epoch C3-A 训练。之后运行冻结多样本 v3、样本集合评分 v3、保存同一采样循环生成数组，并完成 Research Decision Review。

本轮未访问 confirmation/test/optical 载荷，未训练、推理或计算模型指标；不改变任何阶段 gate，不授权第二 seed 或 C3-B。

## 2026-11-23 实际结果

Sidecar 已在 C3-A v3 同一采样循环启用，保存 200 个 development 身份、19 个来源组、每身份 4 个 draw，共 800 个 Flow 样本及匹配确定性基线。NPZ 为 439,898,403 字节。高值代理按每身份 noisy pseudo-target 第 99 百分位及阈值并列规则计算；Flow 减基线来源组等权差：高值区域绝对误差 +0.01691（95% 区间 [+0.01427,+0.01980]）、均值比 −0.01644（[−0.01917,−0.01389]）、峰值比 +0.06462（[+0.05899,+0.07021]）、饱和比例 +0.03667（[+0.02753,+0.04642]）。这仅是归一化 8-bit 表示域代理，不作物理散射体解释。
