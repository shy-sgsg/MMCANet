# JDSR 项目重启说明

本文档基于对当前工程代码和已有笔记的只读梳理，目的是帮你在搁置一段时间后快速恢复上下文：这个项目当时在做什么、代码主线在哪里、已经跑到什么程度、下一步应该怎么接着做。

## 1. 一句话定位

当前工程围绕 **SAR/DBS 图像增强** 展开，核心目标是：从低分辨率、带相干斑、可能带失焦/模糊退化的 SAR 图像中，重建更清晰、更高分辨率、且尽量保留 SAR 物理散射特性的结果。

代码里有两类思路：

1. **当前主线：MMCANet v4**

   - 用配对 SAR/光学图像训练一个双流网络。
   - 训练时从原始 SAR 构造低分 SAR 输入，再让网络恢复原始 SAR。
   - 光学图像主要作为结构/边缘引导，而不是让网络照搬光学纹理。
2. **Baseline / 对照线：Early-FusionCascadeJDSR**

   - `SAR2SAR -> SwinIR` 的串行级联。
   - SFT 条件融合网络。
   - 评估脚本提供 PSNR、SSIM、RMSE、ENL、EPI、TBR 等指标。

工程里的 `BasicSR` 和 `deepdespeckling` 更像外部框架/依赖库，主要被早期 baseline 调用，不建议从它们开始重新读。

## 4. 当前主线：MMCANet v4

### 4.1 数据流

`train_v4.py` 中的数据流为：

```text
SAR_HR/MR 原图
  -> SAR 预处理 log_clip
  -> 物理退化生成 SAR_LR
      1. 频域低通截断
      2. 可选各向异性模糊
      3. 下采样
      4. Gamma 乘性斑点噪声
  -> 作为网络 SAR 输入

OPT_HR 光学图
  -> resize 到 SAR_LR 尺寸
  -> 作为网络光学输入

TwoStreamFrequencyGuidedUNet(SAR_LR, OPT_LR)
  -> SAR_SR/clean 输出
  -> 与 SAR_HR/MR 伪真值计算损失
```

### 4.2 SAR 预处理

公共函数在 `MMCANet/src/train_attention_sr_common.py`：

```python
preprocess_sar_tensor(norm_mode="log_clip", log_scale=20.0, clip_low=0.1, clip_high=99.9)
```

当前逻辑是：

1. SAR 先 clamp 到 `[0, 1]`。
2. 做 `log1p` 压缩动态范围。
3. 用软百分位归一化，默认 `0.1% ~ 99.9%`。
4. 注释里明确写了：这是为了避免过强散射点被硬截断成“平顶山”，尽量保留极端强散射点。

这点很重要，因为后面论文里如果强调“强散射体保护”，预处理不能把强点先抹没。

### 4.3 退化模型

v4 默认使用 `physical` 退化：

```text
frequency_truncation -> anisotropic_blur(optional) -> downsample -> gamma_speckle -> clamp
```

默认参数在 `train_v4.py`：

```text
--input-downsample-size 128
--downsample-factor 2
--lr-degradation-mode physical
--degrade-freq-window-size 64
--degrade-anisotropic-blur False
--degrade-speckle True
--degrade-speckle-looks 2.0
```

直观理解：

1. 原图 256x256。
2. 频域只保留中心 64x64，模拟分辨率损失。
3. 默认不加额外各向异性模糊。
4. 下采样到 128x128。
5. 加 Gamma 乘性斑点噪声。
6. 网络用 `upscale=2` 回到 256x256。

### 4.4 模型结构

模型类是：

```python
TwoStreamFrequencyGuidedUNet
```

结构大致是：

```text
SAR encoder: 1 通道输入
OPT encoder: 3 通道输入
deep_cross_attn: 在 bottleneck 做空间交叉注意力
decoder: 主要走 SAR skip connection
shallow_fusion: 顶层用光学浅层特征做通道门控
PixelShuffle: 按 upscale 放大
out_conv + sigmoid: 输出 1 通道 SAR
```

一个关键设计是：解码阶段主要拼 SAR 的 skip，不直接大面积拼光学 skip。这样比暴力光学融合更保守，能降低把光学纹理/阴影注入 SAR 的风险。

### 4.5 v4 损失函数

`train_v4.py` 的总损失：

```text
Total =
  lambda_rec       * Charbonnier(SAR_out, SAR_gt)
+ lambda_lowfreq   * low_frequency_l1_loss(SAR_out, SAR_gt)
+ lambda_guided_tv * optical_guided_tv_loss(SAR_out, OPT_high_freq)
+ lambda_ratio     * local_mean_ratio_loss(SAR_out, SAR_gt)
```

默认权重：

```text
--lambda-rec 0.5
--lambda-lowfreq 1.0
--lambda-guided-tv 0.001
--lambda-ratio 0.2
```

各项含义：

1. **Charbonnier 重建损失**

   - 比 L1 更平滑，能减少训练震荡和块状感。
2. **低频一致性损失**

   - 把输出和 SAR 伪真值先平均池化，再算 Charbonnier。
   - 用于确保宏观辐射结构不跑偏。
3. **光学引导 TV**

   - 先把光学转灰度，再用 Laplacian 提取高频。
   - 用光学高频边缘控制 TV 权重。
   - 平坦区鼓励 SAR 输出平滑，边缘区减少过度平滑。
   - 这比直接用光学 RGB 更安全，因为去掉了颜色/阴影低频污染。
4. **局部均值比损失**

   - 计算 `SAR_gt / (SAR_out + eps)` 的局部平均是否接近 1。
   - 目的是抑制棋盘格、假锐化和局部辐射比例异常。

## 5. v4 怎么重新跑

### 5.1 最小训练命令

在项目根目录运行：

```bash
python MMCANet/src/train_v4.py --epochs 50
```

这会默认读取：

```text
data/sar
data/opt
```

并保存到：

```text
checkpoints/0519/
```

默认权重前缀：

```text
mmcanet_0519_v2
```

### 5.2 建议先用 mini 数据冒烟

如果很久没跑，建议先不要直接 2000 张全量训练，先跑：

```bash
python MMCANet/src/train_v4.py \
  --sar-dir data/sar_mini \
  --opt-dir data/opt_mini \
  --epochs 2 \
  --batch-size 2 \
  --num-workers 0 \
  --save-dir checkpoints/smoke_v4 \
  --save-prefix smoke_v4
```

这一步只验证：

1. 环境依赖没坏。
2. 数据路径没错。
3. 网络输入输出尺寸能对上。
4. loss 是 finite，不是 nan。
5. checkpoint 能正常保存。

### 5.3 推理命令

`infer_v4.py` 的 `--weights` 是必填：

```bash
python MMCANet/src/infer_v4.py \
  --sar-dir data/sar_mini \
  --opt-dir data/opt_mini \
  --weights checkpoints/0519/mmcanet_0519_v2_final.pth \
  --out-dir outputs/v4_infer \
  --use-physical \
  --debug-physical
```

输出目录包括：

```text
original/       # 原始 SAR 可视化
degraded/       # 物理退化后的输入
output/         # 模型输出
optical/        # 光学图
quad/           # 2x2 对照图
debug_physical/ # 退化过程每一步，开启 --debug-physical 时保存
```

`--use-physical` 很关键：它决定推理时是否也把原始 SAR 先退化成 LR，再送入网络。如果你的权重是按 v4 默认 physical 退化训练的，推理最好也带上它，否则输入分布会不一致。

## 7. Baseline 怎么用

### 7.1 级联 baseline：SAR2SAR + SwinIR

入口：

```text
Early-FusionCascadeJDSR/cascade_baseline.py
```

主要用途：

1. `infer`：先 SAR2SAR 去斑，再用 SwinIR 超分。
2. `finetune`：在当前 SAR 数据上微调 SwinIR。

注意点：

1. 它依赖 `BasicSR` 的 SwinIR 实现。
2. 它依赖 `deepdespeckling` 的 SAR2SAR。
3. 有 checkpoint 格式兼容处理，比如去掉 SwinIR checkpoint 里的 `attn_mask`。
4. 默认 `output-16bit` 开启，SR 输出会保存为 16-bit PNG。

这条线更像“传统强 baseline”，不是当前最该继续改的主线。

### 7.2 SFT baseline

入口：

```text
Early-FusionCascadeJDSR/sft_baseline.py
```

模型：

```text
SFTSRNet
```

它用 SAR 走主干，用光学 + 光学高频作为条件，通过 SFTLayer 调制 SAR 特征。训练损失是 L1 + SSIM。

这条线适合和 MMCANet v4 对比：一个是 SFT 条件调制，一个是双流 encoder + cross attention + shallow guide fusion。

### 7.3 指标评估

入口：

```text
Early-FusionCascadeJDSR/eval_metrics.py
```

可算：

```text
psnr, ssim, rmse, enl, epi, tbr
```

典型命令：

```bash
python Early-FusionCascadeJDSR/eval_metrics.py \
  --pred-dir outputs/v4_infer/output \
  --gt-dir outputs/v4_infer/original \
  --output-csv outputs/v4_infer/metrics.csv
```

注意：这里的 GT 其实是“原始带噪/中高分 SAR 伪真值”，不是干净真值。所以 PSNR/SSIM 只能反映伪监督一致性，不能直接代表去斑质量。更有意义的是结合 ENL、EPI、TBR 看：

1. ENL：平坦区去斑是否变好。
2. EPI：边缘是否保留。
3. TBR：强散射目标是否被削弱。

## 8. 研究思路现在应该怎么接

已有笔记里有一个重要转向：不要把光学先验当成战场动态目标本体的真实先验。更合理的是：

1. 对第一阶段 2D 图像增强，光学可以作为历史结构/边缘辅助。
2. 但模型不能依赖光学生成“看起来像光学”的 SAR。
3. 目标是 SAR/DBS 自身的物理一致增强：去斑、超分、聚焦增强、强散射点保护。
4. 后续论文叙事可以落在“自监督物理退化闭环 + 可选跨模态结构引导 + SAR 物理约束”。

从代码角度看，v4 已经比较贴近这个方向：

1. 低分输入由 SAR 自身退化构造，形成自监督闭环。
2. 光学只以高频/边缘形式参与 TV 引导。
3. SAR 重建与低频一致性仍然是主约束。
4. ratio loss 防止网络用假纹理或棋盘格骗过视觉。

下一步不要急着换 Diffusion/Mamba。先把 v4 的实验链条补完整，它是论文第一阶段最容易落地的基座。

## 10. 目前最可能的风险点

### 10.1 光学引导可能引入幻觉

虽然 v4 已经只取高频引导 TV，但网络本体仍然有 OPT encoder 和 cross attention。如果光学和 SAR 时相不同或配准不好，模型仍有可能把光学边缘带进 SAR。

建议后续实验必须做：

1. 光学错配测试。
2. 光学移位测试。
3. 去掉光学输入或置零光学输入测试。

### 10.2 推理输入分布要和训练一致

v4 训练默认从 HR SAR 退化到 LR SAR。如果推理时不带 `--use-physical`，就会把原始 SAR 直接当 LR 输入，分布不一致。

### 10.3 指标里的 GT 不是真干净图

当前训练目标是原始 SAR，它仍然带斑点。PSNR/SSIM 高不一定代表更干净，只代表更像原图。论文评价必须配 ENL/EPI/TBR 和人工选区图。

### 10.4 SAR2SAR 权重路径不完全统一

baseline 里有些默认路径指向：

```text
weights/sar2sar.pth
deepdespeckling/deepdespeckling/sar2sar/saved_model/sar2sar.pth
```

重新跑 baseline 前要确认哪个权重实际存在、格式是否能被当前兼容逻辑加载。

### 10.5 `train_v4.py` 和 `infer_v4.py` 当前是未跟踪文件

这两个文件对当前主线很重要，但 git 状态显示它们还没被跟踪。后续确认可跑后，建议把它们和这个说明文档一起提交，避免再次丢上下文。

不要一上来读 `BasicSR` 或 `deepdespeckling` 全源码。它们是依赖/参考，不是当前研究逻辑的核心。

## 12. 下一次开发建议

最务实的下一步是做一个 `scripts/run_v4_recheck.sh` 或 `note/实验记录_YYYYMMDD.md`，固定住以下内容：

1. 当前环境。
2. 使用权重。
3. 推理命令。
4. 输出目录。
5. 指标表。
6. 典型样例图编号。
7. 主观观察：噪声、边缘、强散射点、棋盘格、光学幻觉。

只要这条实验闭环跑稳，再继续上更复杂的蒸馏、Diffusion 或 Mamba 才有意义。现在代码最该补的是“实验可复现性”和“证据链”，不是再开一个新网络分支。
